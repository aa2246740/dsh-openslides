## 决策与实施边界

1. **前置资料明确化。** 正常生成所需资料与分块应在计划/写页前明确；合稿失败必须给出准确的文件、分块和下一步调用。恢复已有项目时按已有持久记录继续，不要求重写页面来取悦进度计数器。元素/页范围编辑保持原有授权边界。
2. **审阅按依赖执行。** 当前页版本 → 渲染与图像凭据 → 视觉审阅；当前文稿需要整稿审美审阅时，先取得overview。issues只表示未解决问题，正面说明不能塞入issues。拒绝应给可执行的恢复步骤，不能替Agent伪造通过记录。
3. **进展来自持久事实。** 新增有效资料回执、当前版本的渲染/审阅、完成条件减少、合稿/导出等实质推进应避免误停；反复读同一资料、重复审阅同一版本、失败调用、无效回执不能无限重置预算。不得仅提高阈值或把读取工具全部豁免。
4. **取消与失败分开。** 系统暂停导致未派发的工具显示已取消及上游原因。页面已保存但合稿未完成必须明确，不把历史已恢复错误当成当前阻断，也不隐藏原始错误记录。

## 进一步定位

Host 的 `commit_design` / `write_todo` 在调用 PresentationRun 前就执行 `commitPlan`，而 PresentationRun 原来的这两个分支只记录采用资料，未进入 domain 的必读校验。这使 ADR0008 的前置约束在真实入口失效；这次计划提交时，11个基础资料分块均未读。修复必须在任何计划持久副作用之前拒绝缺读，并考虑本次候选采用资料。

另一个恢复缺口在界面：普通左侧对话属于范围受限的页面修改，不应借它恢复整份生成。暂停且已有页、未合稿的同一会话需要独立“继续完成生成”入口，直接继续原会话，保留页内容，防止重复提交，并以真实会话状态确认完成。

进展守卫只接受首次出现的有效完成事实；当前有效事实减少、重新出现、上下文切换或重复工具输出均不算新进展。真正的布局拒绝仍需模型根据缺陷修页；不能把所有拒绝都转成继续渲染同一页。
