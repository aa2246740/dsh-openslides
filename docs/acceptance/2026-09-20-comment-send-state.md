# 批注发送状态验收 · 2026-09-20

用户指出：批注已经出现在对话里，发送区却仍保留同一附件。根因是前端等整个模型回合结束才清除输入，同时把 running、failed 都当成待发送意见。

## 交付行为

| 阶段 | 对话 | 输入框 |
| --- | --- | --- |
| 请求尚未接收 | 不冒充已发送 | 保留草稿；拒绝时可直接重发 |
| Host 接收请求 | 原消息下显示“已发送 · 正在修改” | 立即清除本次文字和批注 |
| 修改通过范围校验 | 原消息显示“已完成” | 保留用户后来写的新文字 |
| 已接收后失败 | 原消息说明结果并提供“重试” | 不回填旧附件，不覆盖新草稿 |
| 重试 | 重发原批注和原补充说明 | 保留当前新草稿 |
| 刷新 | 恢复持久的原消息与结果 | 已发送附件不再返回 |

发送回执来自 Host 已落盘的用户消息；成功结果来自实际文稿范围校验。两者分开，避免把模型接收当成修改完成。之前的失败记录不会被后续重试改成成功。删除了批注回合末尾重复的结果提示，动态发送/停止按钮的提示也随状态更新。
