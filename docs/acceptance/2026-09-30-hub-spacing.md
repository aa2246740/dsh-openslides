# Hub 首页间距修复

## 请求与改动

用户指出首页输入框到「继续协作」的空白不和谐，要求修复，而不只是解释。
本轮保留输入卡片宽度、字体、warm/ink 主题、项目列表和模型菜单，只调整纵向节奏。

| 间距 | 修改前 | 修改后 |
| --- | --- | --- |
| 输入框 → 最近项目，桌面 | 120–220px，随窗口高度增长 | 48px |
| 输入框 → 最近项目，窄屏 | 同桌面规则 | 32px |
| 顶部，1000px 高桌面窗口 | 220px | 120px，上限 128px |
| 顶部，窄屏 / 短窗口 | 88px / 至少 96px | 72px / 64px |
| 说明文字 → 输入框，桌面 / 窄屏 | 44px / 32px | 32px / 24px |
| 页面底部 | 120px | 64px |

`hub.html` 更新样式版本，避免用户验收时继续读取旧缓存。
设计契约见 `DESIGN.md` 的「Hub 连续工作区」。

## 验证

- 新增回归先在旧布局失败，1920×1080 实测项目间距 216px、顶部 237.59px。
  修复后两主题均通过 1920×1080、1440×1000、1024×768、390×844、
  320×640、1440×420 的间距与横向边界检查。
- 普通窗口（高度至少 640px）首屏可见最近项目第一行。420px 短窗口优先保留
  输入区，最近项目通过自然滚动查看，不强行把所有内容挤入一屏。
- `hub-launch-dom.test.mjs` 5/5；native-web 串行全套 181/181；client 3/3；
  `oracle:validate`、`git diff --check` 通过。
- Hub create / launch / projects / settings 三轮均 95/95，最后一轮有两个 CPU
  负载进程。使用测试项目验证打开、删除确认与持久化，没有删除用户项目。
- 真实服务读取目录、模型能力和订阅状态，状态接口返回 200；浏览器 `pageerror`
  为空。菜单打开/关闭不撑高输入框，两主题窄屏与短窗口未发生横向溢出。
